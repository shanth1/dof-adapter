# DOF / LAB

Локальный браузерный стенд для расчёта DOF-адаптера: **M42 → рассеивающий экран → конденсаторы → макролинзы → камера**.

## Запуск

Нужен Node.js **22.12+ или 24+**.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`).

```sh
npm run build       # TypeScript + production-сборка в build/
npm run preview     # просмотр production-сборки
npm test            # аналитические проверки ядра
npx playwright install chromium
npm run test:e2e    # браузерные сценарии desktop/mobile
```

Приложение и шрифты работают локально; серверная часть и внешние API не нужны. Для публикации достаточно статических файлов из `build/`. JSON-проекты сохраняются в localStorage и экспортируются на диск. Снимки сравнения живут в текущей сессии; изображение пользователя не включается в JSON.

## Первый эксперимент

1. Выберите отдельное матовое стекло или матирование **плоского входа** первого конденсатора.
2. Задайте размер кадра. Для полного 35-мм кадра — 36 × 24 мм.
3. Добавьте свои элементы из меню. Можно отключать, переворачивать, менять местами, добавлять до 20 линз в каждой группе.
4. Уточните материал, световой диаметр, толщины, покрытия и геометрию. В режиме **f+n** поверхности вычисляются с допущением о форме; в режиме **радиусов** именно R1/R2 определяют фактическую мощность, а поле f служит справочной спецификацией.
5. Укажите физический EFL камеры, активную область сенсора, диафрагму и МДФ. Эквивалентные «24 мм» телефона нельзя вводить как физический EFL.
6. Нажмите «Применить расчётный фокус». Кнопка доступна только для положительной достижимой дистанции.
7. В «Подбор и отчёт» найдите положение камеры. После применения предварительный вариант пересчитывается более плотной выборкой.
8. Проверьте карты освещённости, фокуса и нелинейности. Увеличьте число лучей и убедитесь, что показатели стабилизируются.
9. Исследуйте диапазон фокусов конденсатора, диоптрий макролинзы, зазоров или матирования. Меняется **первый** элемент соответствующей группы, а камера перефокусируется, если может.
10. Сохраните варианты, сравните компромиссы и экспортируйте JSON-отчёт либо печать/PDF.

**Нормализация просмотра** по умолчанию включена, чтобы видеть структуру изображения при больших световых потерях. Отключите её, чтобы сравнивать яркость при фиксированных выдержке/ISO. Она не влияет на численные результаты.

## Исходные компоненты

| Профиль | D, мм | f, мм | центр, мм | край, мм | Достоверность |
|---|---:|---:|---:|---:|---|
| D55.5F120C8.5T1.7 | 55,5 | 120 | 8,5 | 1,7 | Размеры предоставлены пользователем |
| D52F80C9.2T2.4 | 52 | 80 | 9,2 | 2,4 | Размеры предоставлены пользователем |
| Френель f50 / f70 | 60* | 50 / 70 | 1,5* | 1,5* | Только f подтверждено |
| Макро +10 D | 52* | 100* | 3* | 1,5* | Пример, не паспорт изделия |

`*` — стартовое предположение. Световые диаметры, материалы, покрытия и пропускание стеклянных линз также предполагаемые.

Начальная цепочка содержит две D55.5 и пример макролинзы +10 D. D52 и обе Френеля доступны в каталоге.

У D52 при предположении BK7 паспортные f и толщины не согласованы со сферической PCX. Стенд сообщает это. Кнопка вывода геометрии использует:

```text
sag = центральная толщина − толщина края
R = (D²/4 + sag²)/(2 sag)
n = 1 + R/f   (только сферическая PCX в воздухе)
```

Это математический вывод, **не доказательство материала**. Погрешности размеров, фаски, асферическая форма и неизвестное определение диаметра меняют результат.

Профили Pixel 10 Pro содержат подтверждённые производителем диафрагмы main/ultrawide/tele: f/1,68 / f/1,7 / f/2,8. EFL, физический размер сенсора, МДФ, положение зрачка и режим разрешения — редактируемые оценки. Необходимо отличать оптический формат сенсора от его реальных размеров и учитывать кроп режима видео.

## Система отсчёта

- M42: номинальный рабочий отрезок 45,46 мм от опорной плоскости байонета.
- Z=0 расчётной цепочки: входная матовая поверхность / плоскость кадра.
- Зазор каждой линзы: от выходной вершины предыдущего элемента до входной вершины этой линзы. После отдельного стекла — от его выходной поверхности.
- При матировании конденсатора зазор первого активного конденсатора принудительно нулевой. Поверхность должна быть плоской и лежать в плоскости экрана.
- Зазор камеры: от последней выходной вершины до выбранной опорной плоскости камеры. Сдвиг зрачка прибавляется к нему.
- Эквивалентная главная плоскость камеры и её зрачок совмещены в данной модели.
- Фокус камеры / МДФ должны быть приведены к дистанции **от этой эквивалентной плоскости**, не автоматически к дистанции от сенсора.
- R1/R2 положительны, если центр кривизны находится справа от вершины (+Z); `0` в редакторе означает плоскость.

## Математика

### Параксиальная модель

ABCD использует вектор `(y, nθ)`. Перенос внутри материала: `B=d/n`; поверхностная мощность `(n₂−n₁)/R`. Толстолинзовые матрицы учитывают толщину и ориентацию. Для системы до камеры:

```text
дистанция видимого объекта s = B/D
сенсор камеры v = f·s_focus/(s_focus−f)
увеличение при сопряжении m = −v/B
EFL = −1/C
H1 = EFL·(1−D)
H2 = Z_output + EFL·(A−1)
```

Фокусировка Гелиоса — тонколинзовая оценка смещения сопряжённых плоскостей относительно номинального рабочего отрезка, а не трассировка его внутренних элементов.

### Геометрическая трассировка

Трёхмерные пересечения со сферическими поверхностями, векторный закон Снеллиуса, отражение Френеля, TIR и отсечение световыми диаметрами. Поддержаны наклон вокруг Y и децентровка X стеклянных линз. Френель — идеальная тонкая линза с заданной толщиной и пропусканием; наклон и канавки не трассируются.

Для каждой точки экрана выбираются точки входного зрачка камеры по детерминированному диску. Newton shooting ищет выходящий с экрана луч, попадающий в выбранную точку зрачка. Телесный угол получается из численного якобиана, с параксиальным приближением на границе апертуры.

### Радиометрия

Учитываются cos⁴-падение освещённости объектива, f-number, пропускание экрана, отражения поверхностей и угловая диаграмма матирования. Гауссова модель моментно приближает выходной зрачок объектива и его свёртку с рассеиванием. Ламбертов экран не зависит от направления падающего пучка.

Сбор света уже включает потери стекла, поэтому повторно умножать эти величины нельзя. Освещённость сенсора использует параксиальную площадь изображения. EV сравнивается с идеальным объективом f/2 до пересчёта площади на сенсор; закрытие диафрагмы включено. ISO и выдержка не меняют пропускание.

### Резкость и зоны аберраций

Параксиальный дефокус камеры отдельно показан как диаметр круга нерезкости. Карта фокуса использует 2×RMS точного пучка, взвешенного переносимым потоком, и приближённые вклады зерна, дефокуса Гелиоса и Airy. Airy каждой эквивалентной тонкой линзы оценивается как `2,44λN·v/f`; вклад объектива пересчитывается через увеличение на сенсор. Это согласованные индикаторы, но не волновая PSF или полная MTF. Карта нелинейности показывает среднее отклонение точного пучка от параксиального переноса.

Тестовое изображение использует центральную оценку гауссова размытия и карту освещённости. Реальные полевые PSF и геометрическое искажение изображения не воспроизводятся этой иллюстрацией; для зон риска служат отдельные карты.

## Точность и ограничения

Этот стенд пригоден для исследования конфигураций, сопряжения, апертурных ограничений и компромиссов. Он **не является валидированной цифровой копией произвольного изделия** только по его f и диаметру.

Не реализованы: полная оптическая схема Гелиоса/камеры, асферики, дисперсионная трассировка, измеренная BSDF матирования, внутренняя дисторсия и виньетирование камеры, блики и многократные отражения, канавочная дифракция Френеля, RAW/HDR/ISP и переключение модулей телефона. Число Аббе и шаг Френеля сохраняются справочно; n следует задавать для выбранной длины волны.

Модель shooting не разрешает все многозначные пути возле каустик. При B≈0 радиометрия недостоверна. Без рассеивающей поверхности необходима отдельная aerial-image модель; текущий режим даёт геометрию, но не подтверждённый световой прогноз.

Поиск камеры — одномерный ограниченный перебор, не глобальный подбор всех линз. Параметрическое исследование помогает сравнивать другие f/диоптрии/расстояния; состав и количество элементов меняются редактором. Предварительный расчёт поиска: 5×3 точек и 12 лучей. Основной: 19×13 точек и 8–256 лучей на точку.

## Проверки и структура

- `src/model.ts` — схема, профили, валидация импорта.
- `src/optics.ts` — матрицы, поверхности, лучи, радиометрия, поиск, исследование.
- `src/worker.ts` — вычисления вне UI-потока.
- `src/main.tsx` — редактор, SVG, Canvas, результаты, экспорт.
- `src/optics.test.ts` — аналитические тесты.
- `tests/workbench.spec.ts` — редактор, сохранение, импорт, поиск, карты, экспорт и мобильная вёрстка.

Тесты проверяют аналитические случаи и интеграционные сценарии. Сравнение с измерениями реального адаптера и независимым оптическим пакетом ещё не выполнено.
